# 2026-07-07 多軸最速 PID 制御

## 変更目的

最終目標を x 軸中心の高速移動から、x/y/z の相対移動指令に対して同じ制御思想を適用する構成へ改定した。

重点は次の通り。

- x/y/z の各軸で、最大加速、制動距離予測、急制動、PID 精密停止へ遷移する。
- 風、干渉、物理的妨害で目標から離れた場合も、センサが復帰すれば再収束を続ける。
- 逆走や最良到達点からの大きな離脱は軸ごとに検知し、安全停止する。
- pitch/roll の水平合成入力が過大にならないよう、ベクトル量を制限する。

## 実装内容

- `AxisRapidState` を追加し、軸ごとに高速フェーズを管理するようにした。
- `move_relative_mm()` で x/y/z それぞれに高速移動フェーズを適用した。
- `control_phase_y`, `control_phase_z`, `predicted_remaining_y_mm`, `predicted_remaining_z_mm`, `stopping_distance_y_mm`, `stopping_distance_z_mm` をログへ追加した。
- CLI に `--max-roll`, `--brake-roll`, `--max-throttle`, `--brake-throttle` を追加した。
- 自動 PID 更新は x/y/z 全軸の最終誤差が異常に大きくない場合だけ行うようにした。
- 実機なしテストで x/y/z の最大加速と急制動フェーズを確認した。

## 理論上の限界

CoDrone EDU 単体の光学フロー、ToF、IMU だけでは、強風や接触外乱下で絶対位置を数学的に厳密保証することはできない。センサが位置を更新できない、床面特徴が不足する、機体が押さえ込まれる、または通信遅延が続く場合、制御器は出力を上げ続けず安全停止する。

厳密な最終位置保証をさらに高めるには、外部モーションキャプチャ、UWB、AprilTag などの外部測位を追加し、この制御器の `SensorSnapshot` 入力へ融合する必要がある。

## 次回の実機確認

1. `python main.py --x-mm 300 --no-auto-tune`
2. `python main.py --y-mm 300 --no-auto-tune`
3. `python main.py --z-mm 200 --no-auto-tune`
4. 各軸 3 回ずつ、`final_error_*`, `duration_sec`, `stale_ratio`, `control_phase_*` を確認する。
5. 単軸が安定してから `python main.py --x-mm 300 --y-mm 300 --z-mm 200 --no-auto-tune` を試す。

## 注意

`DEFAULT_MAX_THROTTLE` は上下方向の急変による危険を避けるため 80 にした。最速優先の実験で十分な空間がある場合のみ、`--max-throttle 100 --brake-throttle 100` を指定して比較する。

- `DEFAULT_BRAKE_ACCEL_MM_S2 = 20` は実測速度に対して保守的すぎ、急制動開始が早くなりやすい。

追加修正:

- 精密停止中は、対象軸の誤差が `max(60mm, 初期誤差の20%)` を超えるまで runaway 停止しないようにした。
- `DEFAULT_BRAKE_ACCEL_MM_S2` を `160` に変更し、短距離で早すぎる制動を減らした。

## 追加実行 2 本の解析

ログ:

- `flight_logs/pid_flight_20260707_164950.jsonl`
- `flight_logs/pid_flight_20260707_165019.jsonl`

### x=300mm 再試験

結果:

- `termination_reason = runaway`
- `final_error_x_mm = 301.8`
- `final_error_y_mm = -83.1`
- `final_error_z_mm = 38.2`
- `peak_speed_x_mm_s = 652.3`
- `brake_start_error_x_mm = 174.7`
- `brake_start_speed_x_mm_s = 302.3`

解釈:

- `DEFAULT_BRAKE_ACCEL_MM_S2 = 160` は強すぎ、300mm 試験では制動開始が遅れた。
- 急制動後に `settle` へ入った時点で、反対方向への戻り速度が大きく、従来の回復出力 `35` では足りなかった。

追加修正:

- `DEFAULT_BRAKE_ACCEL_MM_S2` を `90` に下げた。
- `settle` 中に目標から離れる速度が `80mm/s` を超える場合、回復出力を速度比例で最大出力まで増やすようにした。

### y=300mm 試験

結果:

- 実行コマンドは `python main.py --y-mm 300 --no-auto-tune`
- ただしログ上は `target_x_mm = 100`, `target_y_mm = 300`
- `termination_reason = runaway`
- `final_error_y_mm = 232.5`
- `peak_speed_y_mm_s = 366.7`

解釈:

- CLI の `--x-mm` デフォルトが `100` だったため、y 単独試験になっていなかった。
- 実機ログでは `roll=-100` の初動で `y` 誤差が増加しており、y 正方向の roll 符号が逆だった。

追加修正:

- CLI と `run_flight()` の x デフォルトを `0mm` に変更した。
- `FIXED_CONTROL_SIGNS["roll"]` を `-1.0` から `1.0` に変更した。

次回推奨:

```powershell
python main.py --x-mm 300 --no-auto-tune
python main.py --y-mm 300 --no-auto-tune
```

確認:

- y 試験のログが `target_x_mm = 0`, `target_y_mm = 300` になっていること。
- y 初動で `error_y_mm` が増え続けず、単調減少へ向かうこと。
- x 試験で急制動後の戻り速度が抑えられ、`final_error_x_mm` が改善すること。

## 追加実行 2 回目の解析

ログ:

- `flight_logs/pid_flight_20260707_165327.jsonl`
- `flight_logs/pid_flight_20260707_165345.jsonl`

### x=300mm

結果:

- `termination_reason = runaway`
- `final_error_x_mm = 168.2`
- `brake_start_error_x_mm = 118.4`
- `brake_start_speed_x_mm_s = 269.8`
- `peak_speed_x_mm_s = 395.3`

解釈:

- 前回よりオーバーシュートは小さくなった。
- ただし `brake` から `accelerate` へ再加速した同じ制御周期で runaway 判定が走って停止した。
- これは実機挙動ではなく状態遷移ロジックの順序問題。

追加修正:

- `brake -> accelerate` の再加速直後は、その制御周期だけ runaway guard を抑制する。

### y=300mm

結果:

- `target_x_mm = -13.1`, `target_y_mm = 290.8`
- `termination_reason = runaway`
- `final_error_y_mm = 527.2`
- `peak_speed_y_mm_s = 623.8`

解釈:

- `target_x` の混入は解消された。
- `roll=+100` で `error_y_mm` が `290.8 -> 527.2` に増え続けたため、roll 符号は `+1` ではなく `-1` が正しい。

追加修正:

- `FIXED_CONTROL_SIGNS["roll"]` を `-1.0` に戻した。

次回推奨:

```powershell
python main.py --x-mm 300 --no-auto-tune
python main.py --y-mm 300 --no-auto-tune
```

確認:

- x は `brake -> accelerate` 直後に即 runaway しないこと。
- y は `roll=-100` で `error_y_mm` が減少方向へ向かうこと。

## 追加実行 3 回目の解析

ログ:

- `flight_logs/pid_flight_20260707_165911.jsonl`
- `flight_logs/pid_flight_20260707_165932.jsonl`

### x=300mm

結果:

- `termination_reason = runaway`
- `final_error_x_mm = 185.5`
- `brake_start_error_x_mm = 244.0`
- `brake_start_speed_x_mm_s = 310.2`
- `peak_speed_x_mm_s = 382.3`

解釈:

- `brake -> accelerate` 直後の即 runaway は解消した。
- ただし短距離で 3 回目の再加速まで行き、逆速度が大きくなって停止した。
- 300mm 級では再加速を多く許すとバンバン制御が暴れやすい。

### y=300mm

結果:

- `termination_reason = runaway`
- `final_error_y_mm = 117.1`
- `best_error_y_mm ≈ 55.8`
- `peak_speed_y_mm_s = 496.0`

解釈:

- `roll=-100` に戻したことで `error_y_mm` は `295.8 -> 55.8` まで減少し、符号は正しい。
- その後 `settle` 中に目標方向へ戻っている区間でも、最良点から離れたという理由で runaway 停止した。

追加修正:

- 300mm 級では高速再加速パスを最大 2 回に制限した。
- `brake -> accelerate` の再加速後、2 回の fresh サイクルだけ reverse/runaway guard を猶予する。
- `settle` 中に `error * velocity > 0`、つまり目標へ戻っている場合は runaway と数えない。

次回推奨:

```powershell
python main.py --x-mm 300 --no-auto-tune
python main.py --y-mm 300 --no-auto-tune
```

確認:

- x が 3 回目の再加速へ入らず、PID 精密停止へ移行すること。
- y が `best_error_y_mm` から一時的に離れても、目標へ戻っている限り安全停止しないこと。

- `flight_logs/pid_flight_20260707_170244.jsonl`

### x=300mm

結果:

- `termination_reason = runaway`
- `final_error_x_mm = 223.7`
- `brake_start_error_x_mm = 229.2`
- `brake_start_speed_x_mm_s = 194.8`
- `peak_speed_x_mm_s = 336.6`

解釈:

- `brake -> accelerate` 直後の即停止は解消した。
- ただし 300mm で再加速を許すと、再度逆速度が出て停止している。
- 300mm 級では再加速せず、最初の加速・制動後に PID 精密停止へ渡す方が安定する。

### y=300mm

結果:

- `termination_reason = runaway`
- `final_error_y_mm = 350.2`
- `best_error_y_mm ≈ 192.8`
- `peak_speed_y_mm_s = 198.1`

解釈:

- y の初動は目標方向へ進んでおり、符号は正しい。
- ただし再加速後に x/z/yaw が大きく乱れ、最後は `settle` 中の離脱判定で停止した。
- ここでも短距離再加速が主な不安定要因。

追加修正:

- `initial_abs_error <= 400mm` では高速再加速を禁止した。
- まだ開始時より十分目標に近い場合は、逆速度や最良点からの離脱だけでは安全停止しないようにした。

次回推奨:

```powershell

```

- 300mm 試験で `pass=2` の再加速ログが出ないこと。
- `brake` 後に `settle` へ入り、PID 補正を継続すること。
- `termination_reason` が `runaway` でなくなるか、少なくとも duration が伸びること。

## 追加実行 5 回目の解析

ログ:

- `flight_logs/pid_flight_20260707_170506.jsonl`
- `flight_logs/pid_flight_20260707_170526.jsonl`

### x=300mm

結果:

- `termination_reason = runaway`
- `final_error_x_mm = 406.0`
- `target_x_mm = 338.9`
- `brake_start_error_x_mm = 261.3`
- `brake_start_speed_x_mm_s = 201.7`

解釈:

- 再加速を禁止しても、300mm で最高速加速と急制動を入れると `settle` 移行後に大きく離脱した。
- 300mm 級では制動距離予測よりも、機体応答遅れ・床面/気流・センサ更新遅れの影響が大きい。
- 短距離では bang-bang の最速モードより、最初から PID で速度を抑えて収束する方が最終位置精度が高い。

### y=300mm

結果:

- `termination_reason = runaway`
- `final_error_y_mm = 382.7`
- `target_y_mm = 306.9`
- `brake_start_error_y_mm = 239.0`
- `brake_start_speed_y_mm_s = 376.9`

解釈:

- y 方向も最高速加速から急制動へ入った後、ロール戻しと姿勢の乱れで目標から離脱した。
- 符号は正しいが、300mm では最高速モードのエネルギーが大きすぎる。

追加修正:

- x/y の高速 bang-bang 制御は `abs(target) >= 500mm` のときだけ有効にした。
- z は既存テストと安全余裕を維持し、`abs(target) >= 300mm` から高速モードを許可する。
- 300mm の x/y 試験は PID 精密制御だけで実行し、長距離だけ最高速加速・急制動を使う方針に変更した。

次回推奨:

```powershell
python main.py --x-mm 300 --no-auto-tune
python main.py --y-mm 300 --no-auto-tune
```

確認:

- 300mm の x/y で `control_phase` が `settle` のままになること。
- `termination_reason` が `runaway` でなく、最終誤差が縮小すること。
- 500mm 以上の距離では `accelerate -> brake -> settle` が維持されること。
