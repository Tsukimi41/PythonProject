# 2026-06-30 変更詳細

## 背景

依頼時点の目標は、CoDrone EDU を PID 制御で指定量だけ精密に移動させることであった。さらに、風・干渉・物理的妨害があっても最終位置を厳密に合わせたいという要求がある。

既存コードは `main.py` から `drone_precision.py` を呼び出す構成であり、実際の制御本体は `drone_precision.py` に集約されていた。

確認した情報源:

- 公式ドキュメント
  - `https://docs.robolink.com/docs/CoDroneEDU/Python/Drone-Function-Documentation`
- ローカルライブラリ実装
  - `.venv/Lib/site-packages/codrone_edu/drone.py`

確認した主要 API:

- `pair(portname=None)`
- `get_battery()`
- `reset_gyro()`
- `takeoff()`
- `hover(duration=0.01)`
- `reset_move_values(attempts=3)`
- `get_position_data(delay=0.01)`
- `get_motion_data(delay=0.01)`
- `set_roll(power)`
- `set_pitch(power)`
- `set_throttle(power)`
- `set_yaw(power)`
- `move(duration=None)`
- `land()`
- `close()`

## 変更前の問題点

既存ログとコードから、次の問題が確認できた。

1. 制御の重心が `x` 軸に偏っていた。
2. `y` と `z` は補助的に抑え込むだけで、主目標として厳密に合わせる設計になっていなかった。
3. ログのサマリが `x` 軸中心で、横流れや高度ズレの追跡が弱かった。
4. 位置センサが同値を返して停滞している区間がログ内にあり、その間も通常制御を継続していた。
5. ゲインの自動調整が単純で、多軸の誤差傾向を十分反映していなかった。
6. 停止判定が甘く、速さ・安定性・多軸同時整定の観点が不足していた。

## 実施した変更

## 1. PID プロファイルの再設計

対象箇所:

- `drone_precision.py` の `default_pid_profile()`
- `load_pid_profile()`
- `save_pid_profile_for_distance()`

変更内容:

- 各軸の設定に `kv` を追加した。
  - これは速度に対する減衰項であり、速すぎる突入を抑える目的がある。
- 各軸の設定に `min_output` を追加した。
  - 小誤差時に出力が弱すぎて動かない領域を避ける目的がある。
- 旧プロファイルファイルに `kv` や `min_output` がなくても、デフォルト値で補完できるようにした。

意図:

- 最速と精度は通常トレードオフになるが、速度減衰を入れることで「遠距離では強く、近距離では止まりやすい」制御に寄せる。
- 実機では静止摩擦や推力の不感帯があるため、微小出力だけでは動かないケースを避ける。

## 2. 状態推定層の追加

対象箇所:

- `SensorSnapshot`
- `StateEstimate`
- `_compute_state_estimate()`

変更内容:

- 生の位置・姿勢読み出しとは別に、制御に使う推定状態 `StateEstimate` を導入した。
- 連続サンプルから `x/y/z` 速度を推定する処理を追加した。
- センサの更新が止まった場合は速度を徐々に減衰させ、`stale_cycles` を増やすようにした。
- `pos_fresh`, `motion_fresh` を各サンプルに保存するようにした。

意図:

- PID の D 項を単なる誤差差分ではなく、状態変化と速度を踏まえて扱えるようにする。
- センサ更新が止まった区間で強い制御を打ち続けるのを避ける。

## 3. PID 計算器の刷新

対象箇所:

- `PIDController`

変更内容:

- `kp`, `ki`, `kd` に加えて `kv` を持つ PID に変更した。
- 出力式を以下の考え方に変更した。

```text
output = kp * error
       + ki * integral
       + kd * derivative_term
       - kv * measurement_rate
```

- センサが不健全なときは積分を弱める仕組みを追加した。
- `gain_scale` によって、距離や誤差の大きさに応じて一時的にゲインを変えられるようにした。

意図:

- 高速移動時に単純な P 制御だけだと突っ込みすぎてオーバーシュートしやすい。
- `-kv * 速度` を入れることで、速度が乗った時点で自然に制動がかかる。

## 4. 多軸同時制御への整理

対象箇所:

- `move_relative_mm()`

変更内容:

- 目標を `x/y/z/yaw` の 4 軸で同時に扱う構成へ変更した。
- 各軸ごとに別 PID を常時回し、すべての誤差を毎周期評価するようにした。
- 誤差が大きいときと近傍で異なる出力上限を使うようにした。
- `y` や `z` のずれが大きすぎる時は `pitch` の上限を意図的に絞るようにした。

意図:

- 目標は最終的に `x, y, z` 指令値送信であるため、初めから多軸設計にしておく必要がある。
- 前進だけを優先して横や高さを後回しにすると、総合到達時間と最終精度が悪化する。

## 5. センサ停滞時の安全制御

対象箇所:

- `move_relative_mm()`

変更内容:

- `stale_cycles >= 4` で「センサ不健全」と見なし、各軸コマンド上限を大きく絞るようにした。
- `stale_cycles >= 10` で安全停止するようにした。

意図:

- 実機では通信や位置更新の停滞が起こりうるため、ログ上の同一位置連続返却を無視してはいけない。
- 不正確な状態推定のまま強く動かすより、安全側に倒す方がよい。

## 6. 停止判定の厳格化

対象箇所:

- `is_settled_state()`
- `FlightLogAnalyzer._estimate_settling_time()`

変更内容:

- 誤差の許容値を `x/y/z/yaw` すべてに対して明示的に設定した。
- 速度条件も入れて、位置誤差だけでなく「本当に止まりかけているか」を見るようにした。
- 一定時間連続で安定した場合のみ整定完了と見なすようにした。

意図:

- 一瞬通過しただけなのか、実際に狙った位置へ止まれたのかを分離して判定する。

## 7. ログ構造の強化

対象箇所:

- `ControlSample`
- `FlightLogWriter`
- `_record_sample()`
- `_record_summary()`

変更内容:

- 1 サンプルごとに次の情報を保存するようにした。
  - `pos_fresh`, `motion_fresh`, `stale_cycles`
  - `x/y/z/yaw` 誤差
  - `x/y/z` 速度
  - `pitch/roll/throttle/yaw` コマンド
  - 各軸の出力上限
  - 各 PID の積分値
- ログ先頭に `metadata` レコードを書き、参照ドキュメント URL と PID プロファイルを残すようにした。

意図:

- 「なぜその場でそのコマンドを出したのか」をあとから再構成できるようにする。

## 8. 履歴解析の自動化

対象箇所:

- `FlightLogAnalyzer.analyze_history()`
- `analyze_recent_logs()`
- `run_flight()`

変更内容:

- 直近ログの summary を集めて中央値を計算し、`flight_logs/last_history_analysis.json` に保存するようにした。
- 実行前に過去傾向をコンソールへ出すようにした。

意図:

- 1 回だけうまくいった値に引っ張られず、直近全体の傾向を見るため。

## 2026-06-30 実行結果の追加解析

対象ログ:

- `flight_logs/pid_flight_20260630_163702.jsonl`

結果:

- `duration_sec = 1.8774`
- `final_error_x_mm = 1967.1`
- `final_error_y_mm = -35.7`
- `final_error_z_mm = -759.7`
- `stale_ratio = 0.6774`

原因分析:

1. 移動開始基準が `x=0, y=0, z=0` のまま確定していた。
2. その直後に本来の高度 `z≈816.7mm` が入ったため、制御器が「目標高度 0mm へ戻す」と誤解した。
3. その結果、`throttle_cmd=-32` が継続して入り、高度制御が実験目的と逆方向へ働いた。
4. 位置更新がしばらく来ない区間で `stale_cycles` が急増し、安全停止条件に達した。

実施した追加修正:

1. 離陸後に新鮮な位置サンプルを複数取得し、平均化した基準位置を使うようにした。
2. 安全停止は `stale_cycles >= 18` かつ `elapsed >= 1.0s` に緩和した。
3. 距離プロファイルを `500mm/2000mm` 固定から、任意距離をファイル名化して扱う方式へ変更した。

期待する効果:

- 高度基準の誤認識を防ぐ。
- 位置更新がやや粗いだけのケースで即停止しにくくする。

## 2026-06-30 100mm 実験再解析に基づく追加修正

対象ログ:

- `flight_logs/pid_flight_20260630_170026.jsonl`

結果:

- `final_error_x_mm = 45.47`
- `final_error_y_mm = 1.15`

期待する効果:

## 2026-06-30 上下振動を受けた追加修正

対象ログ:

- `flight_logs/pid_flight_20260630_171035.jsonl`

結果:

- `duration_sec = 19.9905`
- `final_error_x_mm = 64.16`
- `final_error_y_mm = -44.60`
- `final_error_z_mm = 26.56`

- `peak_speed_z_mm_s = 78.95`

原因分析:

1. 反対方向への暴走は解消したが、`z` 軸は目標近傍でも上下反転が強かった。
2. `error_z_mm ≈ 20` でも `throttle_cmd = -20` が出ており、その後すぐ `+18` 以上へ戻っている。
3. これは、保存済みの `throttle.min_output = 4.0` と、過去の自動調整で増加した `throttle kp/ki` が近距離高度制御を強くしすぎていたためと考えられる。
4. `peak_speed_z` が高いのに `final_error_z` が残っているので、推力不足ではなく減速不足である。

実施した追加修正:

1. デフォルトの `throttle.min_output` を `0.0` に変更した。
2. `load_pid_profile()` でも、保存済みプロファイルに関係なく `throttle.min_output = 0.0` へ正規化するようにした。
3. `|error_z| < 60mm` では `throttle` ゲインを弱めるようにした。
4. `|error_z| < 45mm` と `25mm` で `throttle_limit` を段階的に下げるようにした。
5. 目標へ近づく `z_velocity` が大きすぎるときは、ブレーキ方向へ `throttle_cmd` を寄せるようにした。
6. `|error_z| < 20mm` では `throttle` 積分を減衰し、`|error_z| < 12mm` かつ低速時は `throttle_cmd = 0` とする高度ホールド寄り制御を加えた。
7. 自動チューニングでは、`peak_speed_z` が高い場合に `kp/ki` を上げず、逆に下げて `kv/kd` を増やす方向へ修正した。

期待する効果:

- 目標高度付近での過剰な上昇・下降反復を抑える。
- `z` 軸の整定を改善し、前進軸の評価を邪魔しにくくする。
- 近距離試験での安全性と再現性を上げる。

## 2026-06-30 17:20 600mm 実験解析と収束改善

対象ログ: `flight_logs/pid_flight_20260630_172047.jsonl`

- 結果: 目標近傍には到達したが、高度振動により20秒でタイムアウト

原因:

- `pitch` と `roll` の最低出力が誤差の大きさに関係なく働き、目標近傍でもコマンドがゼロにならなかった。
- `pitch_integral=1251`, `throttle_integral=1017` まで積分が蓄積し、目標近傍の収束を妨げた。
- 高度速度が大きい場合に `kd` と `kv` を増やす自動調整が、通信・機体応答遅れのある高度系のコマンド反転を強めていた。
- 距離の異なる過去ログを同じ履歴中央値に含めていた。

修正:

- 最低出力を `pitch: 30mm以上`, `roll: 25mm以上` の誤差帯だけに適用。
- 出力飽和中は積分を進めない anti-windup を追加。
- 軸ごとの積分有効範囲と速度条件を追加し、目標近傍では積分を減衰。
- 積分上限を `pitch=600`, `roll=500`, `throttle=450`, `yaw=60` に制限。
- 高度軸を `kd<=0.025`, `kv<=0.18` に制限し、高速振動時は両ゲインを下げるよう自動調整を修正。
- 通常飛行前の履歴解析は、指令距離が `±10%` または `±25mm` 以内のログだけを対象化。

次回は同じ `600mm` 条件を再試験し、`pitch_integral`, `throttle_integral`, `z_velocity_mm_s` と整定時間を比較する。

## 2026-06-30 17:27 最高速・急制動制御への変更

対象ログ: `flight_logs/pid_flight_20260630_172711.jsonl`

- 指令距離: 約 `600mm`
- 最終誤差: `x=1065.9mm`, `y=16.3mm`, `z=34.8mm`
- stale 比率: `0.73`
- 結果: 最初の約1.5秒だけ正方向へ進み、その後 `pitch=+45` のまま逆方向へ離脱してタイムアウト

解析結果:

- 位置パケットが0.3秒から0.8秒間隔になる区間が多かった。
- 従来は位置パケット間の変位を約0.08秒の制御周期で割っていたため、`-312mm/s` など過大な速度を算出していた。
- 逆走判定カウンタを stale 周期ごとにゼロへ戻していたため、有効な位置更新では悪化が続いても停止できなかった。
- 異常終了ログでも自動調整を保存し、600mmプロファイルを悪化させていた。

実装変更:

- 150mm以上のx移動を `acquire -> accelerate -> brake -> settle` の状態機械へ変更。
- `accelerate` は最大ピッチ `100`、`brake` は最大逆ピッチ `100` を使用。
- `v^2/(2a) + v * センサ遅延 + 余裕距離` で停止距離を予測し、目的地の手前から最大制動を開始。
- 位置更新が0.30秒止まった場合も、速度が残っていれば予防制動へ移行。
- 制動後は通常PIDへ戻し、目的地を精密に追い込む。
- 速度計算の時間幅を、制御周期ではなく実際の位置パケット更新間隔へ修正。
- 逆方向速度を有効な位置更新2回で観測した場合は即停止。
- 最良誤差から `max(25mm, 指令距離の5%)` 悪化した状態を2回観測した場合も停止。
- `runaway`、センサー停止、過大誤差の飛行結果はPID自動調整へ使用しない。
- 異常飛行で上書きされた600mmプロファイルを、飛行開始時の値へ復元。

追加テスト:

## 2026-06-30 17:42 急制動モデルの実測補正

対象ログ: `flight_logs/pid_flight_20260630_174211.jsonl`

- 最大加速開始: `t=0.42s`, `pitch=+100`
- 制動開始: `t=2.41s`, 残距離 `489.9mm`, 推定速度 `31.7mm/s`
- 制動終了: `t=5.31s`, 残距離 `326.3mm`, 推定速度 `16.5mm/s`
- 最良x誤差: `39.4mm`
- 終了: `runaway`, 最終x誤差 `72.8mm`
- stale 比率: `0.73`

改善した点:

- `+100` と `-100` の最大加速・最大制動指令は実機へ正しく送信された。
- 逆走ガードが働き、前回のような1000mm超の離脱を防止した。
- 異常終了のためPIDプロファイルは更新されなかった。
- 高度誤差は最終 `0.6mm` まで抑えられた。

残った問題:

- 位置更新が0.33秒止まっただけで予防制動へ入り、目的地の約490mm手前で急制動した。
- 位置欠損中に速度を減衰させ、最大加速指令も `12` へ制限していた。
- 設定減速度 `900mm/s^2` に対し、ログから求めた実効減速度は約 `13.8mm/s^2` だった。
- 早く停止した後は残り326mmをPIDだけで追い込み、時間を失った。
- PID追い込み中に逆向き速度が生じた際、`pitch=7..15` では回復できなかった。

修正:

- 既定の制動減速度を実測に近い `20mm/s^2` へ変更。
- stale中は最後の有効な前進速度を保持し、残距離予測と停止距離計算に使用。
- staleだけを理由に制動へ移行する分岐を削除。
- 高速区間では位置更新待ちでも最大加速または最大制動を維持し、1.2秒のセンサー停止ガードで保護。
- 制動終了時に120mm以上残っていれば、最大3パスまで再加速。
- PID精密停止中に30mm超の誤差と逆向き速度を検出した場合、`pitch=35`で回復。
- 高速区間の逆走停止は有効更新2回のまま維持し、PID精密停止中だけ4回に延長。

旧ログを新しい停止距離式で再計算すると、最初の制動候補は残距離約 `72mm` となり、490mm手前での早期制動は解消される見込み。
