## 2026-06-30 100mm 実験の再解析

- 対象ログ: `flight_logs/pid_flight_20260630_170026.jsonl`
- 条件:
  - 目標距離: `x=100mm`
  - 固定符号使用
  - `pitch_sign = -1`
- 結果:
  - `final_error_x_mm = 45.47`
  - `final_error_y_mm = 1.15`
  - `final_error_z_mm = 26.05`
  - `duration_sec = 4.48`
  - `stale_ratio = 0.8056`
  - `peak_speed_x_mm_s = 174.64`

解釈:

- このログでは、開始時 `x_mm = -43.64` から終了時 `x_mm = 8.16` へ進んでおり、`x` は目標方向へ前進している。
- したがって、今回の実行に関しては `pitch_sign = -1` を直ちに誤りと判断しない。
- 支配的な問題は符号ではなく、位置センサ更新の間隔が長いことに対して制御周期と安全停止条件が厳しすぎた点である。
- 終了直前は `stale_cycles = 18` で安全停止しているが、その時点でも `x` 誤差は縮小途中だった。
- 今後は `x` の到達率改善と `z` の残差抑制を優先して詰める。

今回の修正方針:

- `stale_cycles` 中心の停止判定をやめ、`stale_duration_sec` を導入する。
- 制御周期を `0.04s` から `0.06s` に緩め、センサ更新周期に近づける。
- stale 中も小さな出力で追従を継続し、停止は「更新停止時間」が十分長い場合のみに限定する。

推奨する次回試験距離:

- 第一候補: `100mm` 再試験
- 第二候補: `150mm`

理由:

- 今回は向き確認よりも、stale 判定修正後に `100mm` の到達率がどこまで改善するかを見る段階である。
- `100mm` で `|final_error_x_mm| <= 20` に近づけば、次に `150mm` か `200mm` へ伸ばす判断がしやすい。

## 2026-06-30 反対方向進行の再評価

- 対象ログ: `flight_logs/pid_flight_20260630_170651.jsonl`
- 条件:
  - 目標距離: `x=100mm`
  - 保存済みプロファイルの符号: `pitch_sign = -1`
- 結果:
  - `final_error_x_mm = 2415.33`
  - `final_error_y_mm = -51.50`
  - `final_error_z_mm = 63.94`
  - `duration_sec = 19.96`
  - `stale_ratio = 0.0370`
  - `peak_speed_x_mm_s = 951.47`

解釈:

- 今回は `stale` が主因ではない。`stale_ratio` は低く、位置更新は十分入っていた。
- 初期状態で `error_x_mm = 95.79` に対し `pitch_cmd = -14` が出ており、その後 `x_mm` は `-57.58 -> -65.50 -> ... -> -2377.12` と一貫して負方向へ離脱した。
- したがって、現在の実機では `pitch_sign = -1` は明確に誤りであり、前回の「符号ではない」という判断はこのログで否定された。
- 100mm 指令に対して 2m 以上逆走しているため、以後は符号をプロファイルから学習・継承させず、固定値として扱うべきである。

今回の修正:

- `pitch_sign` を固定正方向へ戻し、保存済みプロファイルに入っていた誤った符号を無視するよう変更した。
- 短距離開始直後の `pitch_limit` を抑え、初動の暴走エネルギーを下げた。
- `x` が目標から連続して逆方向へ離脱した場合に、安全停止するガードを追加した。

推奨する次回試験距離:

- `100mm` のみ

理由:

- まずは反対方向進行が完全に止まったことを確認する必要がある。
- 次回は距離を伸ばす段階ではなく、符号修正後の初動 1 秒以内の挙動確認が最優先である。

## 2026-06-30 上下振動の解析

- 対象ログ: `flight_logs/pid_flight_20260630_171035.jsonl`
- 条件:
  - 目標距離: `x=100mm`
  - `pitch_sign` は固定正方向
- 結果:
  - `final_error_x_mm = 64.16`
  - `final_error_y_mm = -44.60`
  - `final_error_z_mm = 26.56`
  - `duration_sec = 19.99`
  - `stale_ratio = 0.1276`
  - `peak_speed_z_mm_s = 78.95`

解釈:

- 反対方向への暴走は止まったが、高度軸は目標付近でも `throttle_cmd` が大きく反転し、上昇と下降を繰り返していた。
- 例として、`error_z_mm = 20.1` 付近で `throttle_cmd = -20`、その後 `error_z_mm = 30.3` で `throttle_cmd = +18` へ切り替わっており、近距離域の `z` 制御が攻めすぎている。
- 保存済みプロファイルの `throttle.min_output = 4.0` と、増加し続けた `throttle kp/ki` が、この上下反復を強めていた可能性が高い。
- `x` は前進しているが、上下振動が残っているため前進精度にも悪影響が出ている。

今回の修正:

- `throttle.min_output` を `0.0` に固定し、目標近傍で無理に上下指令を出さないようにした。
- `|error_z| < 60mm` では `throttle` ゲインを弱め、`|error_z| < 45mm` と `25mm` で出力上限も段階的に下げるようにした。
- `z` 方向へ目標に近づく速度が大きすぎるときは、速度ブレーキを入れて減速を優先するようにした。
- `|error_z| < 20mm` では積分を減衰させ、`|error_z| < 12mm` かつ低速時は `throttle_cmd = 0` とする高度ホールド寄りの制御を追加した。
- 自動チューニングでも `peak_speed_z` が高すぎる場合は、`throttle kp/ki` を上げるのではなく下げ、`kv/kd` を増やす方向へ変更した。

推奨する次回試験距離:

- `100mm` のみ

理由:

- 次は前後距離より先に、高度軸の整定が改善したかを見るべき段階である。
- `z` の上下振動が収まるまでは、距離を伸ばしても解析が混ざる。
